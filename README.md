# code-pipeline

A DeepSeek Harness plugin for **one-click code standardization**: a sidebar panel with
the workspace code file tree, single / multi / select-all picking, and ten built-in
language presets that apply a consistent style to the files you pick.

> Status: v0.1.0, P0 languages only. Anything outside the ten languages below is
> listed with a `跳过` badge and is never modified.

## Install

```powershell
# from a DeepSeek Harness profile, pointing at this checkout
# (the plugin manager links the directory; it is not published to npm)
dsh plugin add link:D:/05_Code/code-pipeline
```

Then reload the GUI page once — the Client half is injected into the boot graph at
page load, so a newly installed bundle appears only after a refresh.

## What is in the repository

| Path | Role |
| --- | --- |
| `index.js` | Host half: HTTP API under `/dsh-code-pipeline/api`, and the `code_list_files` / `code_standardize` agent tools |
| `client.js` | Client half: left-rail icon (`sidebar.panellist`) and the main panel (`main`, key `code-pipeline`) |
| `lib/languages.js` | Language registry: extension → language, P0 vs non-P0 vs non-code, skipped directories |
| `lib/tree.js` | Workspace scanner and tree builder, path confinement, `.gitignore` subset |
| `lib/presets.js` | Preset loader over `presets/*.json` |
| `lib/standardize.js` | Orchestrator: classify → engine → idempotency gate → optional write |
| `lib/engines/index.js` | Engine adapters with graceful degradation |
| `lib/engines/text.js` | Deterministic whitespace rules (Makefile, PowerShell, fallback) |
| `presets/*.json` | The ten P0 presets (generated by `scripts/gen-presets.mjs`) |
| `cordis.patch.yml` | Bundle patch inserting the `code-pipeline` row |
| `locale/{en,zh}.json` | Plugin title, description, detail document |
| `docs/DETAIL.md` | The plugin-page document shown by Plugin Manager |
| `test/pipeline.test.mjs` | Acceptance-mapped tests (10 cases) |
| `test/client-sim.mjs` | Runs `client.js` against a fake module loader to verify slot registration |
| `scripts/gen-presets.mjs` | Authoring source for all presets (rule text, tier, source URL) |
| `scripts/smoke.mjs` | End-to-end fixture run |

## P0 presets

| Language | Preset | Engine | Depth | Rules | Config |
| --- | --- | --- | --- | --- | --- |
| Go | `go` | gofmt (WASM) | format | 10 (F4 / S5 / X1) | `presets/go.json` |
| TypeScript | `typescript` | Biome (WASM) | full | 9 (F3 / S5 / X1) | `presets/typescript.json` |
| JavaScript | `javascript` | Biome (WASM) | full | 8 (F3 / S4 / X1) | `presets/javascript.json` |
| Python | `python` | ruff format (WASM) | format | 9 (F5 / S4 / X0) | `presets/python.json` |
| HTML | `html` | Biome (WASM) | format | 6 (F5 / S0 / X1) | `presets/html.json` |
| Makefile | `makefile` | built-in text rules | text | 6 (F5 / S0 / X1) | `presets/makefile.json` |
| CSS | `css` | Biome (WASM) | format | 5 (F4 / S0 / X1) | `presets/css.json` |
| C++ | `cpp` | clang-format (WASM) | format | 5 (F3 / S1 / X1) | `presets/cpp.json` |
| Shell | `shell` | shfmt (WASM) | format | 5 (F2 / S2 / X1) | `presets/shell.json` |
| PowerShell | `powershell` | built-in text rules | text | 7 (F5 / S1 / X1) | `presets/powershell.json` |

Rule classes: **F** format (applied automatically) · **S** style (reported, never
auto-applied) · **X** capability note. Every rule carries a tier (`T1` official text,
`T2` official tool default, `T3` de-facto standard, `T0` local decision) and a source
URL, so the panel can show provenance instead of asserting authority it does not have.

`depth` means what actually ran: `full` = formatted **and** lint diagnostics collected,
`format` = formatted only, `text` = whitespace rules only. A missing engine degrades a
language to `text` and the report marks it `degraded`.

## Use it from the panel

1. Open the left rail and choose **Code pipeline**.
2. Pick a workspace in the header when more than one is registered.
3. Expand folders, check files, or press **Select all** (code files with a preset only).
   The header shows `selected / selectable` at all times.
4. **Check** reports what would change and writes nothing. **Standardize** writes.

## Use it from a conversation

```
code_list_files        — inventory with language and support status
code_standardize       — mode: "report" | "fix", paths: [...] or all: true
```

## Verify

```powershell
node --test test/pipeline.test.mjs   # 10 acceptance-mapped cases
node test/client-sim.mjs             # client slot registration contract
node scripts/smoke.mjs               # fixture workspace end to end
```

## Limitations

- Interface / function normalization is **out of scope**: only the rules listed in
  each preset file are applied, nothing beyond them.
- Makefile and PowerShell have no formatter engine; they get deterministic whitespace
  rules only.
- Binary files, dependency directories (`node_modules`, `dist`, `target`, `.venv`, …)
  and generated artifacts are excluded from the tree, so select-all cannot reach them.
- Style findings come from the engine's lint pass and are reported with file, line,
  rule and message; they are not rewritten because the engine classifies those fixes
  as unsafe.
